# UX specs

Design specifications for the web app. A spec is authoritative for layout, states, copy and visuals;
[`docs/decisions/`](../decisions/) is authoritative for architecture and contracts. Supersede a spec
by revising it in place and bumping its status line — the developer should only ever read the current
one.

| Doc | Covers |
| --- | --- |
| [`core-practice-ux.md`](core-practice-ux.md) | App shell, routes, exercise runner and its states, feedback timing, piano keyboard component, progress, settings, visual language, accessibility, copy deck. |
| [`tokens.css`](tokens.css) | The design tokens from that spec, ready to copy to `apps/web/src/lib/styles/tokens.css`. |
